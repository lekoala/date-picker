# Changelog

## 0.6.0 — 2026-10-24

### Removed

- Endpoint dragging on `<date-picker range>`. The drag was a second interaction machine (pointer capture, travel threshold, trailing-click suppression, per-gesture endpoint identity) around rules the range machine already owns. The picker now moves a bound only through a calendar activation (`activateDate()` / `dateactivate`); an application that wants a pointer gesture writes the public API (`calendar.activateDate()` for availability plus the cancelable veto, then `picker.range`, then native `input`/`change` on the bound it moved). See [DECISIONS D9](docs/DECISIONS.md). A tested recipe ships in [CALENDAR-INTEGRATION.md](docs/CALENDAR-INTEGRATION.md); touch handling, cursor affordance and the discard of a draft in the other bound stay application-owned.
- `DateRangeController` is no longer presented as public API in `docs/API.md`. The class was never exported by the package, so this is a documentation correction, not an API removal. Its internal `projectEndpoint()`, `moveEndpoint()` and the `endpoint` argument of `previewRange()` are gone.

### Changed

- The range `dateactivate` path has one entry point: click and keyboard share the same activation machine. `PickIntent` no longer carries an endpoint.
- Attributes are prepared offline and normalized at connect: a detached element no longer reflects or rewrites `value`/`min`/`max`/`display`, while getters keep returning canonical values. Invalid constraints are dropped when the element connects.

### Fixed

- A source load aborted by a reconnect can no longer clear the tracking of a newer load for the same month. `ensureDate()` reuses the in-flight request instead of aborting it and starting another one, so an activation is not refused by a load the component itself cancelled.
- `validate()` stops as soon as the session it started in is dead and returns authored native validity. A stale range validation no longer writes order errors on the rebuilt instance, and a stale single-mode validation no longer rewrites time-order validity on the new companions.
- Disconnecting a calendar removes its `data-loading` marker.

## 0.5.3 — 2026-10-24

### Fixed

- Prevent stale validation and deferred interactions from overwriting newer state or surviving lifecycle changes.
- A field commit now belongs to the connection that started it. Disconnecting or moving the picker while a typed date is still being validated cancels that work: the reconnected instance rebuilds from the live DOM and ignores the old result instead of clearing a newer value, writing a false "unavailable" validity or a stale hidden ISO, or emitting a late `valuechange`/`rangechange` (single and range mode).
- Stabilize calendar announcements, range placeholders, and invalid date/month attribute handling.
- Keep internal implementation details out of published TypeScript declarations.

## 0.5.2 — 2026-10-23

### Fixed

- The standalone build forwards its classic script's CSP nonce to the injected stylesheet, allowing nonce-protected styles without `unsafe-inline`.
- Keep activation intent tracking internal instead of exporting its `WeakMap` through the public calendar module and declarations.
- A form reset after a runtime `locale` change no longer swaps day and month: a reset default generated by the picker is reformatted with the new locale (an author-provided or app-changed `defaultValue` is left untouched).
- `<date-picker>` validates its initial value on connection, so a value outside `min`/`max`, disabled by `isDateDisabled` or refused by the source is reported invalid without waiting for an explicit `validate()`.
- The calendar year input accepts 9999 (an unrenderable 9999-12 still clamps to 9999-11) and always carries `min`/`max` bounds (1–9999 by default).
- `source`, `dateState`, `renderDay` and `isDateDisabled` on `DatePickerElement`, and `getDateState()` on `DateCalendarElement`, are typed instead of `any`.
- `custom-elements.json` lists the connect-time `range` attribute of `<date-picker>`.
- Two grid picks of the same day while the source is loading no longer commit after the popup closed or a newer interaction superseded them: each activation now carries its own intent instead of sharing one keyed by date.
- A `<date-picker>` inside a disabled `<fieldset>` refuses `show()` and grid commits, like a disabled input (editability now reads `:disabled`, not the `disabled` property).
- `dist/date-picker.min.css` and the CSS embedded in the standalone bundle are minified without lowering modern selectors/logical properties (min CSS 17.3 kB → 8.3 kB, standalone 89.5 kB → 83.8 kB).

### Tooling

- `test:syntax` parses sources with Bun's transpiler instead of `node --check`, which `bun run` redirected to Bun and which then executed the browser modules.
- WebKit browser runs pass: Tab-order tests use Alt+Tab on WebKit, and Chromium-only forced-colors assertions are skipped elsewhere.

## 0.5.1 — 2026-10-18

### Added

- Both `DateCalendarElement` and `DatePickerElement` expose static `setDefaultControlClasses()`, `getDefaultControlClasses()`, `setDefaultMessages()` and `getDefaultMessages()` methods. Classic/CDN scripts can configure shared defaults through `customElements.get("date-picker")` or `customElements.get("date-calendar")`, using the same defaults as the named ESM exports within that build.

### Changed

- Global control-class defaults now refresh connected elements, including instances with partial overrides. Assigning `controlClasses` replaces the previous partial map: omitted roles follow current global defaults, an explicit empty string restores the library skin for that role, and `null` resumes following all defaults. Pickers preserve this inheritance when forwarding overrides to their calendar.
- Global message defaults now refresh connected elements without a messages override, including field validation, format hints, triggers and popup labels. An instance message assignment still merges with the current defaults and pins that setting; assigning `null` resumes following global defaults. Disconnected elements read current defaults when reconnected.

### Fixed

- Writable public properties assigned before custom-element definition are reapplied through their setters on connection instead of shadowing the accessors. Options are applied before controls are built; picker `value` and `range` wait until fields and controllers are initialized. Range mode still requires the `range` attribute.
- Add classic-build regression coverage for shared defaults, live updates, partial overrides, reconnection and properties assigned before definition; include the property-upgrade helper in syntax checks and verify the constructor methods in package checks.

## 0.5.0 — 2026-10-17

### Added

- `controlClasses` on calendars and pickers, plus `setDefaultControlClasses()` / `getDefaultControlClasses()`, let host design systems own header control styling while preserving calendar layout and accessibility.

### Changed

- Update `@lekoala/floating` to `^0.3.1` without changing the picker integration API.
- Reuse bounded caches of Intl date formatters and digit maps. Range previews reuse the rendered day states and update only changed band cells; moving a preview no longer rebuilds accessible labels or invokes application state callbacks. `renderDay` receives the same state used for its cell. Call `calendar.render()` when callback-owned data changes; activation still checks current state.
- Share popup outside-click, reset and Escape listeners between single and range pickers.

### Fixed

- Preserve arbitrary Tailwind/shadcn control classes while HTML-escaping them on rendering; equivalent class assignments no longer rebuild the calendar. Remove redundant normalization and CSS layout declarations, and cover the control-class API in consumer type checks.

- `fixed-weeks` no longer throws at December 9999 with Saturday-first weeks: padding stops at the canonical boundary and retains five full rows. Civil padding now lives in `getMonthWeeks()` through its optional `fixedWeeks` option.
- Fetch source URLs are validated at adapter creation, resolving against the document or worker location. Without either base, relative URLs produce an explicit error instead of silently using localhost.
- Remove an unreachable validity branch in editable field input handling; document the snapshot semantics of global message defaults.

## 0.4.0 — 2026-10-12

### Added

- `datefocus` on `<date-calendar>`: a public seam for the date cell that actually took focus (`{ date, state }`, bubbling, not cancelable), so an application can follow keyboard navigation without reading internal `.dp-*` classes. It observes only: hover never emits it, a disabled day still does (grid navigation stays discoverable), and assigning `focusedDate` without moving DOM focus stays silent.
- `calendar.activateDate(date)`: the availability check plus the cancelable `dateactivate` seam plus selection, as one public path. Click, keyboard and the new endpoint drag all run through it, so a cancelled activation cannot be bypassed by choosing another input device.
- Range preview. While a range is being created, hovering a day or moving the keyboard focus projects the range the next pick would commit onto the band, and the pick commits exactly what was projected. The projection is visual only — no `rangechange`, no field write, no validation, no source request — it reads the month already loaded, and a day known to be unavailable promises nothing. Pointer hover never moves `focusedDate`.
- Endpoint drag on `<date-picker range>`. On a complete range whose ends sit on different days, each endpoint can be dragged with a mouse or pen (pointer events plus capture, armed only once the pointer travels). A handle never crosses the other one, an unavailable cell is not a drop target, `pointercancel` restores the committed band, and the drop runs the same projection and the same `ensureDate` + `dateactivate` path as a click. The popup stays open: a drag adjusts a range, it does not validate it. Touch keeps native scrolling and stays a plain tap.
- `DateRangeController` gains `project()`, `projectEndpoint()`, `previewRange()` and `moveEndpoint()`. Each interaction rule now exists once as a projection; the previews read the same projections the commit applies.

### Changed

- Month navigation uses vertical chevrons: up for the previous month, down for the next, matching PageUp/PageDown. Their orientation stays the same in RTL; accessible labels and navigation behavior are unchanged.
- **Calendar interaction never produces an inverted range** (see DECISIONS D6). While a range is being created, a second pick before the anchor is sorted instead of refused: `10` then `5` now commits `5 -> 10` rather than firing `dateinvalid`; `10` then `10` is a one-day range. A pick that completes a range from the other side is sorted the same way. Text entry keeps the opposite contract and may stay temporarily inverted with an order error.
- A range transition now describes the whole resulting pair (`{ status, endpoint, changedEndpoints, range, activeEndpoint, close? }`) and is applied in a single write, because a sorted second pick moves both bounds at once: one `rangechange`, with synthetic `input`/`change` only on the bounds that moved, and no intermediate inverted pair observable.
- `highlightedRange` now repaints the band in place instead of rebuilding the grid. A live preview no longer drops `renderDay()` nodes or fights the roving focus on every hover.
- A range preview never contributes a range start/end to a day's accessible name, so a proposal is not announced as a committed selection.

### Fixed

- The editable field now accepts the exact text it formats for locales whose `Intl` pattern embeds literal spaces or a suffix (`ko`, `hu-HU`, `bg-BG`, …). Literal segments keep their whitespace and each blank run matches as `\s*`, so `parse(format(d)) === d`; previously retyping `2026. 09. 06.` was rejected and a source load could clear the canonical value (`H1`).
- A `source` reload no longer re-homes the visible month. Re-validations triggered by `dateloadend` (or an observed attribute or `messages` change) commit with `moveDisplay: false`, so navigating the popup keeps the month the user chose instead of snapping `display` back to the selected value's month (`H2`).
- Rendering no longer throws at the calendar bounds. `getMonthWeeks()` stops from the last built week instead of advancing its cursor past the canonical window, the year editor is limited to `1..9998`, and `display` is clamped to the last renderable month, so December 9999 (and January 0001 with a Sunday first day) build a grid instead of raising (`B1`).
- `range.spec.js` freezes the clock in `beforeEach`, so the demo range fixtures stay September-based and the browser suite no longer fails on the current month (`M1`).
- A live range preview now repaints day labels when it is entered or left even if the band bounds are unchanged, so the "a proposal is not a committed selection" accessible-name contract also holds when hovering the anchor that already carries the band.
- Focusing a date whose month is outside the renderable window (e.g. `focusedDate = "0001-01-01"` with Sunday as first day) keeps the focused cell inside the rendered grid, so the roving `tabindex="0"` is never lost, and `previousMonth()`/`nextMonth()` no longer throw at the canonical `0001`/`9999` bounds.


## 0.3.0 — 2026-09-15

### Changed

- Visual rhythm pass (CSS only, no JS/API/DOM change): `--dp-gap` is now `0.375rem`, `--dp-header-block-gap` is `0.75rem`, and week rows use the new `--dp-row-gap` token (`0.375rem`), so the header, weekdays and days read as three separated tiers; the picker panel padding is `0.875rem 1rem`. The header keeps a single uniform horizontal gap: the extra `--dp-nav-gap` between year and prev/next is gone (see Removed).
- Deterministic default palette: neutral chrome (`--dp-bg` `#ffffff`, `--dp-fg` `#1f2328`, `color-mix`-derived muted/border/hover) with one functional accent (`--dp-accent` `#2563eb`, `--dp-accent-fg` `#fff`); hover stays neutral, the range band is accent at 18%, and selected/endpoints/today/focus carry the full accent.
- `today` no longer competes with stronger states: the base rule excludes `selected`/`range-start`/`range-end`, so an endpoint falling on today keeps its own treatment in normal rendering and in forced colors (no HC-specific override).
- Forced-colors block reduced to observed-loss fixes (2px `Highlight` border on selected/endpoints, in-range underline, pinned today marker); the inner ring, bold weight and `GrayText` reconstruction are dropped after capture review. The month select also hands its caret back to the browser there.
- Picker panel shadow is `rgb(15 23 42 / 0.12)`.
- The month select draws its own caret (`appearance: none` + `currentColor` gradient, mirrored under RTL) instead of the UA menulist arrow.
- Default visible-focus language for the direct inputs: the date field and the native time companions get an accent border plus a light halo with `outline: none`, while normal input appearance stays consumer-owned.
- Day cells focus with an inner ring (`outline`, `outline-offset: -2px`) instead of an outer outline: focus stays inside the cell, no longer reads as a second selected state, and never bleeds onto a neighbouring range band. The ring inverts to `--dp-accent-fg` on accent-filled cells. An `outline` (not an inset `box-shadow`) is used because forced colors computes `box-shadow` to `none`, which would erase the keyboard indicator.
- The calendar trigger is now a real button overlaid inside the date field's own box (like the native `input[type=time]` indicator) instead of a separate box joined to the field. The field reserves its place, keeps its border/background, and its own focus ring wraps the trigger; the trigger draws no chrome and shows a small inner ring when focused. Focus is only ever drawn on a real box — no host-level ring, no pseudo-element.
- `<date-picker range>` has one trigger per bound (`start`, `end`), each inserted right after its own field in DOM/tab order, sharing a single popup, calendar, source and state. Activating the other bound's trigger while open switches the active bound and keeps the popup open instead of toggling it shut; each trigger follows its own bound's `disabled`/`readonly` and gets a bound-specific accessible name.
- Closing the single picker returns focus to the control that opened it (field or trigger) instead of always the field. Range keeps restoring the active bound, since a first pick moves the workflow to the other bound.
- All date/time boxes are independently rounded: the from/to time companions are no longer square-cornered against each other, and each keeps its own gap.
- The date field now owns its whole box and its authored radius (the demo drops the old half-radius), which is a **visual contract change** for consumers who styled the field as the left half of a joined pair.

### Added

- `--dp-picker-button-size` (`2.5rem`): the calendar trigger width, also used to reserve `padding-inline-end` on the date field it is painted into.

### Fixed

- `ArrowDown` on the trigger opens the popup and enters the grid, so keyboard users keep a working path after focus returns there.

### Removed

- `--dp-nav-gap`. It only existed to space the prev/next group from month/year, and that irregularity read as an arbitrary hole in a four-control header. The header now uses `--dp-gap` everywhere; consumers who set the token can drop it.

## 0.2.0 — 2026-09-09

### Added

- Native time companions: one or two `input[type=time]` marked `[data-time-start]` / `[data-time-end]` beside the date. They stay fully native (own `name`/`value`/submission, no hidden input, no `picker.time` property); `value` stays a `YYYY-MM-DD` date, the picker only enforces from/to order and aggregates validity in `validate()`. Range mode leaves marked times native with a console warning. Datetime composition + timezone stay application/server-owned (D5).
- `<date-calendar>` month/year controls follow the `Intl` locale order (new `monthYearOrder()` helper; year-first for e.g. `ja` / `zh-CN`). The order is direction-independent: locale decides the linguistic order, `dir` only mirrors the layout.
- RTL through the inherited `dir` (no `isRTL` option): the header grid mirrors, the prev/next glyphs mirror via CSS, and actions plus ArrowLeft/ArrowRight stay chronological. Includes an Arabic-locale smoke test.
- Documented date + native time companions submit contract (`appointment[date]` / `appointment[time]`, from/to, future range projection); the core never builds a combined datetime.
- Five semantic CSS tokens so compact consumers (e.g. a mini-month sidebar) stay on the public surface: `--dp-header-control-size`, `--dp-header-block-gap`, `--dp-nav-gap`, `--dp-year-inline-size`, `--dp-day-radius`. Default rendering is unchanged.
- `month-format="short"` for compact headers: the month select shows abbreviated month names (anything else falls back to `long`); the accessible grid heading always keeps the long form. Forwarded from `<date-picker>` to its popup calendar.

### Fixed

- Keyboard navigation across a month boundary no longer snaps focus back onto the old date when it reappears as outside-month padding (`fixed-weeks` / edge weeks).
- A focused disabled day restores full opacity (muted number kept), so the focus outline and the date stay readable instead of washed out.
- A selected day outside the displayed month keeps accent-contrast text on the accent fill (the outside-month tint no longer overrides selection text).
- Header controls (month select, year input, nav buttons) share explicit vertical metrics, so compact `--dp-header-control-size` values render at equal heights instead of exposing UA padding differences.
- Long month names in a narrow track truncate with an ellipsis instead of painting under the native select caret.

## 0.1.1 — 2026-09-07

### Fixed

- `first-day="7"` no longer falls back silently to Monday: `7` is now a pure Sunday alias of `0`, so passing `@lekoala/calendar`'s ISO 1..7 weekday to the grid keeps the columns aligned. `normalizeFirstDay()` backs `startOfWeek` / `endOfWeek` / `getMonthWeeks` / `weekdayNames` and `CalendarModel`; values `2..6` keep their meaning and other values still throw (helpers) or fall back to `1` (attribute).
- The grid `<h2>` heading is now visually hidden (`dp-visually-hidden`) instead of duplicating the month/year selects while still naming the grid via `aria-labelledby` and keeping its `aria-live="polite"` announcement channel.

### Docs

- `show-week-numbers` documents that the ISO week column renders only when `first-day === 1` (Monday-first); with Sunday-first (`0`/`7`) it is silently withheld.
- `docs/CALENDAR-INTEGRATION.md` no longer recommends `focusedDate` as the agenda anchor: `display` and `focusedDate` are coupled (the roving-tabbable cell must stay visible), so the anchor belongs in application state decorated through `dateState` / `renderDay`. The demo now renders a visible anchor marker.

## 0.1.0 — 2026-09-07

Initial public release. The interaction contract, event names, public styling tokens (`--dp-*`) and component API are frozen; internal DOM/class names remain `.dp-*` implementation details.

### Added

- **`<date-calendar>`** inline calendar primitive:
  - separate `display` (month), `focusedDate` (roving keyboard target) and `value` (selected date); activation exposed as `dateactivate`;
  - `selection="none"` for mini-calendar/navigation use that never touches `value`;
  - `highlightedRange` presentation-only range band (`data-range-start` / `data-in-range` / `data-range-end` + accessible labels, forced-colors aware);
  - month/year navigation, `fixed-weeks`, `show-week-numbers`, `min` / `max`, `isDateDisabled`, `dateState`, `renderDay`;
  - abortable async `source` contract with stale-response protection.
- **`<date-picker>`** editable localized field with hidden canonical `YYYY-MM-DD` submission, native Popover + `@lekoala/floating`, `open-on-focus`, form reset/defaultValue, dynamic `name`/`form`, `readonly` / `disabled`, typed validation against the same resolved date state as the grid.
- **`<date-picker range>`** — two editable fields sharing one calendar surface (`[data-range-start]` / `[data-range-end]`), atomic `range` API with a single `rangechange`, active-endpoint interaction, cross-bound order validation, and supersession of stale async responses.
- **`linkDateRange(start, end)`** — external relationship between two independent pickers.
- **`dates`** pure civil-date helpers without `Date`/timezone/Temporal types in the public API.
- 16 locale message dictionaries (`ar`, `de`, `en`, `es`, `fr`, `hi`, `id`, `it`, `ja`, `ko`, `nl`, `pl`, `pt-BR`, `pt-PT`, `ru`, `tr`, `zh-CN`); all locale-shape formatting comes from `Intl`.
- Custom-elements manifest (`custom-elements.json`), generated `dist/` bundles and TypeScript declarations.

### Known limits

- The popup is non-modal (`aria-modal` absent) by design.
- In-place single-calendar range *selection* interaction is deferred; ranges are chosen through `<date-picker range>` or two linked pickers.
- Human screen-reader matrix (NVDA/VoiceOver/TalkBack) is still to be recorded in `docs/AT-CHECKLIST.md`.
